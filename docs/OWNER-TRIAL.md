# 負責人試用步驟（雲端模式）

## 試用前請準備

1. 向後端索取 Firebase 專案 ID。
2. 向後端索取 Firebase Web API 金鑰。
3. 向後端索取測試用存取碼。
4. 向後端索取測試環境專用 POS 金鑰。
5. 準備一台可開瀏覽器的電腦。
6. 準備一台已安裝 Ultron APK 的機上盒。

> 備註：Web API 金鑰可出現在瀏覽器，屬公開設定。  
> 備註：存取碼供控制端與看板使用（看板由 Android 設定寫入）。

## 在電腦開控制端

7. 開啟控制端網址：https://ultronservice.github.io/milksha-demo/controller/
8. 在「連線方式」選「雲端模式（店內／機上盒）」。
9. 點開「進階設定」。
10. 在「Firebase 專案 ID」填入專案 ID。
11. 在「Web API 金鑰」填入 Web API 金鑰。
12. 在「函式區域」填入 asia-east1。
13. 在「測試用存取碼」填入存取碼。
14. 在「選擇門市」選你的門市。
15. 在「測試環境專用 POS 金鑰」填入 POS 金鑰。
16. 按「連線」。

## 機上盒看板

17. 請 Android 工程師幫機上盒裝好看板設定。
18. 開啟機上盒上的看板 App 或預設看板網址。
19. 確認看板已顯示店名與「可取餐」「製作中」兩區標題。

## 送出叫號

20. 在控制端「2. 模擬 POS」輸入號碼與狀態。
21. 按「新增訂單並送出」。
22. 看機上盒看板是否出現該號碼。
23. 在控制端確認狀態為在線。

## 存取碼錯誤（HTTP 403）時看板行為

若後端回傳 **403**（存取碼錯誤或無權限），機上盒看板**不會**清空已顯示的叫號，也不會對客人顯示連線錯誤文案。此時會停止向雲端**上傳／同步新資料**（`data-upload-stopped` 狀態），但仍約每 **5 分鐘**送一次 **heartbeat**，讓後端知道裝置仍在線。

若在 Ultron 後台已更正存取碼，下一次**重新登入成功**（HTTP 200）後，看板會**自動恢復上傳**；heartbeat 在此期間仍會持續，但單靠 heartbeat 不會解除上傳停止狀態。無需到現場重設機上盒。
