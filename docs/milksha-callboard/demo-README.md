# 迷客夏示範叫號：模擬推送劇本與「新叫到」判斷規則

檔案 `milksha-demo-script.json` 是 10 份前後連貫的完整號碼清單，照順序播放（建議每 5 秒換下一份，播完可從第 1 份重來）。
每份的 `request` 欄位與迷客夏規格一致；`_note`（這份在演什麼）和 `_expectRing`（這份應該響聲的號碼）是給前端與 QA 對照用的，不屬於規格。
示範不接真實系統：簽章填 `DEMO-NO-SIGNATURE`，跑馬燈是空陣列、速度 0，畫面不顯示跑馬燈。

## 畫面怎麼更新
每份清單就是「這家店現在該顯示的全部號碼」。收到新的一份就整個換掉：
- 結尾是 `_Preparing` 的放準備中區，結尾是 `_OK` 的放可取餐區。
- 上一份有、這一份沒有的號碼，直接拿掉，不響聲。
- 清單是空的就清空畫面。
- 號碼一律當文字，不要轉成數字（`P021`、`D08` 這種要照原樣顯示）。

## 怎麼判斷「新叫到，要響聲」
1. 每個號碼用「來源＋號碼」當身分，例如「foodpanda 的 F37」。來源就是 `source_type` 去掉結尾的 `_Preparing` 或 `_OK`。不同平台可能出現一樣的號碼，所以要連來源一起看。
2. 把上一份清單裡「在可取餐區」的身分記下來。
3. 這一份清單裡，每個在可取餐區的號碼，如果上一份不在可取餐區（不管上一份是在準備中還是根本沒有），就是新叫到，要響聲。
4. 上一份就已經在可取餐區的號碼，這次不響。
5. 從可取餐退回準備中、從畫面消失、新進準備中，都不響。
6. 頁面剛打開收到的第一份，只顯示、不響（避免一開機就狂響）。
7. 同一份裡有好幾個新叫到，排隊一個一個響、一個一個閃，不要疊在一起。

## 劇本 10 份在演什麼
1. 開店，空清單，畫面清空。
2. 現場 2 筆、迷點 1 筆進準備中。不響。
3. 現場 1001 轉可取餐，響；新增 foodpanda、Uber Eats 準備中。
4. 1002 和迷點 P021 同時轉可取餐，兩個都響；新增 UDD 和現場 1003。
5. 1001 取完消失，不響；foodpanda F37 轉可取餐，響。
6. Uber U512、UDD D08 轉可取餐，響；1004 沒經過準備中直接出現在可取餐，也響。五種來源都在可取餐出現過了。
7. 尖峰：準備中一次湧進 28 筆，需要翻頁；1003 轉可取餐，響。
8. 尖峰：11 筆同時轉可取餐，可取餐區也需要翻頁，11 個全部響（排隊）。
9. 早先 7 筆可取餐一起被取走，不響。
10. 收尾，只剩 2 筆準備中，其他全部消失，不響。
