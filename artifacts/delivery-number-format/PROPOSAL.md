## B) 依 `sourceType` 檢查 vs「信任雲端」

### 後端建議

看板 **信任雲端**；第二道 **只對 `From_Store` 驗 4 位數字**。

### 提案評估（建議採 **混合**）

| 做法 | 優點 | 風險 |
|------|------|------|
| 只驗門市四碼 | 與雲端分工清楚、改規則少改看板 | 異常 payload（本地 shim、舊快取、未來新 client）可能顯示髒字 |
| 每來源完整驗 | 與雲端雙重保護 | 兩邊規則易漂移 |

**建議保留的第二道（輕量安全網，成本低）：**

1. **`number` 必須是 string**（維持；拒 JSON number）。
2. **`trim` 後長度 0 或 >8 → 丟棄**（對齊硬上限）。
3. **字元白名單**：門市／迷點／熊貓僅 `0-9`；Uber／Udd／未知僅 `A-Z0-9`（英數來源先 `toUpperCase` 再驗）。
4. **門市**：**嚴格 `/^\d{4}$/`**（後端建議保留）。
5. **非門市**：**不逐來源重複雲端長度表**（信任雲端 3–6 等），但若明顯不合（如門市路徑卻含字母）仍丟棄。
6. **`sourceType`／`source_type`**：優先 **`tickets[].sourceType`** 轉成 `number_content`；缺 → **門市**；**無法 `parseSourceType` 的前綴** → 走 **未知 3–6 英數 + ≤8** 或丟棄（需與雲端共識；提案傾 **未知用 3–6 英數安全網**）。

**foodpanda 顯示 `#`**：雲端已是 `6406`；看板 **`formatDisplayNumber(sourceKey, stored)`** 可選加 `#`（**不寫回 dedupe**）。

### 重複判定

- 鍵：**`sourceKey` + 雲端存儲值**（熊貓已是 **無 `#`**，不再去 `#`）。
- **不同來源同號**（門市 `1234` 與 Uber `1234`）→ **兩筆都顯示**（後端定稿）。
- 取代現行「**只看號碼字串**」的 `readyNumbers`／`prepNumbers`。

## 同號不同來源 — 客人分得清嗎？（風險）

| 事實 | 說明 |
|------|------|
| 現行看板 UI | **`renderNumberChip` 只畫號碼**，**沒有**規格書 §2 的來源小標（店／迷／熊／U）。 |
| 若同時上板 `1234` | 客人 **只能看到兩個 1234**，**無法**從畫面分辨門市或 Uber。 |
| 營運影響 | 可能 **拿錯餐**；機率取決於跨來源撞號頻率。 |
| 規格書 | 已假設 **「來源 + 號碼」** 為身分，且設計 **來源標籤** — **產品尚未實作**。 |

**結論：** 在 **僅顯示數字** 前提下，允許跨來源同號 **有實質混淆風險**。  
**緩解（擇一，屬後續產品，非本次程式範圍）：** 實作來源標籤；或 UI 加前綴（如 Uber 顯示 `C7458` 已含字母較不易撞門市四碼）；或營運規則避免跨渠道同號。

## 2) 排版實測（3–6 字與 8 字上限）

### 方法

- `?mode=local&orientation=landscape`，無 `motion=on`。
- 81px Arial／Arimo、`nowrap`、2×5 art 格；**1080p／4K 僅 scale，設計 px 相同**。
- 現行第二道仍擋非四碼 → 截圖以 **DOM 覆寫 `.milksha-num`** 模擬定稿通過後內容。

### 6 字元（右欄 budget ≈ **347px** ink）

| 樣本 | ink 寬 | 右欄 |
|------|--------|------|
| `888888` | ~264 | ✅ |
| `#888888` | ~312 | ✅ |
| `C745890`（Uber 6） | ~322 | ✅ |
| `WWWWWW` | ~459 | ❌（左欄 ~397 也不足） |

### 8 字元（後端硬上限）

| 樣本 | ink 寬 | 右欄 | 左欄 |
|------|--------|------|------|
| `88888888` | ~354 | ❌ | ✅ |
| `12345678` | ~351 | ❌ | ✅ |
| `C8888888` | ~367 | ❌ | ✅（略緊） |
| `#88888888` | ~402 | ❌ | ❌ |
| `WWWWWWWW` | ~612 | ❌ | ❌ |

**解讀：** 定稿業務長度 **≤6** 時，**正常數字／Uber 英數** 在 **右欄可接受**；**6 個 `W` 是極端壓力**（非真實單號）。**8 字元**若真出現，**右欄常放不下**，需 **左欄格、縮字或不允許上板** — 與雲端「上限 8」在 **最窄欄** 有 **視覺衝突**。

### 熊貓 `#` 兩方案（雲端存 `6406`）

| 方案 | 截圖 |
|------|------|
| UI 加 `#`（例 `#6406`） | `board-static-1920x1080.png`、`board-static-3840x2160.png` |
| UI 不加 `#`（`6406`） | `board-fp-nohash-1920x1080.png`、`board-fp-nohash-3840x2160.png` |

### 6 字／8 字壓力圖

- `board-len6-1920x1080.png`、`board-len6-3840x2160.png` — `888888`、`#888888`、`WWWWWW`、`C745890`
- `board-len8-1920x1080.png`、`board-len8-3840x2160.png` — 8 字樣本

## C) 1080p／4K 一格最多幾字？8 字放不放得下？

**兩種解析度答案相同**（同一設計座標）。

| 字元類型 | 右欄（較窄）最多 | 左欄較寬 |
|----------|------------------|----------|
| 數字 `8` | **7** | **8** |
| `#` + 數字 | **`#` + 6 個數字**（共 7 字元） | 再多 1 位數 |
| `C` + 數字 | **7** | **8** |
| 大寫 `W` | **4** | **5** |

**對定稿的對應：**

- **Uber 6、熊貓 6 位數、迷點 4 位數** → **OK**（右欄）。
- **後端硬上限 8 字** → **8 位純數字在右欄略超**（~354 > ~347）；**8 字不建議在右欄假設必 fit**。
- **建議：** 雲端 **業務規則 ≤6** 與排版一致；**8 僅作傳輸上限** 時，看板第二道 **≤8 安全檢查保留**，但 **6 以上可 warn 或僅允許左欄**（若要實作需另案）。

**UI 建議（既有設計優先）：** 熊貓 **可不顯示 `#`**（較省寬）；若品牌要 **`#`**，`#888888`（6+1）仍 **可放右欄**。

## 3) TDD 邊界（公開行為，5 條）

1. **門市** `'1234'` 顯示；`'123'`、`'12345'`、JSON `1234` → 不顯示。  
2. **迷點** `'0912'`（4 位）與 `'578'`（3 位）顯示；**不** forced 大寫。  
3. **Uber** `'c745890'` → 顯示 **`C745890`**（6 位）；**7 位英數** → 依信任雲端策略：通過 ≤8 安全網或丟棄（需與實作選項一致）。  
4. **熊貓** 雲端 `'6406'`；UI 開 `#` 時 DOM 為 **`#6406`**，dedupe 仍 **`fp:6406`**。  
5. **門市 `1234` + Uber `1234`** → **兩筆皆在**；**同來源重複 `1234`** → **一筆**。

加：**ticket 無 `sourceType` → 走門市四碼**。
