本確認書供迷客夏資訊部與奧創對齊試點叫號接收端之合作範圍、串接規格與驗收方式。 技術欄位以迷客夏提供之《叫號機接收端 API 串接規格》及線上討論文件為準（欄位名稱與拼字不可自行修改）。 後端服務於本文統稱奧創接收端。

1. 合作範圍與分工

  • 迷客夏：資訊窗口（IT 聯絡人 Tammy）；協調達鈦 POS 端設定與試點門市；與奧創直接對接整合事宜。
  • 達鈦（POS 送端）：試點時僅更換 endpoint URL 至奧創提供之接收端位址；Request／Response JSON 結構與現行相同，不變更 payload 格式。
  • 奧創：建置並維運奧創接收端（接收 POS 外送之叫號名單、依規格回覆處理結果）；提供門市叫號大螢幕顯示（含現場機上盒與畫面應用）。

2026-10-01 會議決議（試點接收端）：試點改由奧創自建 API 服務作為叫號接收端，承接 POS 外送；不再使用迷客夏現行接收 URL。外送 JSON 與達鈦／迷客夏現行相同；顯示與回覆仍依《叫號機接收端 API 串接規格》。本試點範圍不包含規格未定義之掃碼寫回 POS 或額外欄位。

迷客夏 Tammy（2026-09 對話）已確認：現況全達鈦門市 POS 打迷客夏 URL；試點目標為 POS 直接呼叫奧創接收端；結帳後外送準備中、店員於叫號控制屏完成或掃碼後再由 POS 外送可取餐狀態。

2. 串接規格

串接內容依《叫號機接收端 API 串接規格》；完整欄位、範例與十種 source_type 說明以原文件為準。下列為雙方確認時需共同遵守之摘要（與討論文件一致）。

2.1 Request（POS → 奧創接收端）

主要欄位：isEncrypt、serviceSpecialData_Json（含 target、data.number_content、跑馬燈相關欄位）、merchant_id、account、timeStmp、serviceSpecialData_Json_Md5Hash、signature。

number_content 每筆含 source_type（完整字串比對）、number（必須以字串處理，不可轉整數）。

拼字特殊、不可修改：Request 之 timeStmp（非 timestamp）。

2.2 Response（奧創接收端 → POS）

主要欄位：merchant_id、account、isOK、information、reslut（含 CallingNumberMasterResponse.result、statusCode）、resultMd5、reesultMd5_ServerSignature、isEncrypted。

拼字特殊、不可修改：Response 之 reslut、reesultMd5_ServerSignature。

2.3 外層 isOK 與內層 isSuccess

  • isOK = true：表示 API 層級已正常完成處理。
  • information 與 CallingNumberMasterResponse.result 為 JSON 字串，解析後之 isSuccess 表示是否成功顯示至叫號機；information 為成功或失敗訊息文字。

2.4 建議內層回傳訊息（四種，文字依規格）

情境內層 JSON（示意）
成功{ "isSuccess": true, "information": "資料顯示成功" }
目標未連線{ "isSuccess": false, "information": "目標叫號機尚未連線" }
找不到設備{ "isSuccess": false, "information": "找不到目標叫號機" }
資料錯誤{ "isSuccess": false, "information": "叫號資料格式錯誤" }

簽章、MD5 計算範圍、加密與 HTTP 方法等細節以原規格及雙方另行列印之技術附件為準（見第 7 節待提供項目）。

3. 顯示規則

奧創接收端每次收到之 number_content 代表該 target 對應螢幕此刻應顯示的完整名單（整批覆寫，非單筆追加）。

  • source_type 為 From_Store_Preparing（及規格所列其他 *_Preparing）→ 顯示於準備中區塊。
  • source_type 為 From_Store_OK（及規格所列其他 *_OK）→ 顯示於可取餐區塊。
  • 本批 number_content 中未出現之舊號碼，應自畫面移除。
  • number_content 為空陣列 → 清空叫號畫面（準備中與可取餐區塊）。
  • 每日 03:00（台灣時間） 自動清空所有門市叫號顯示狀態（營運日切換）。
  • newsTicker_content、newsTickerSpeed：POS 仍可依規格外送；試點叫號大螢幕不顯示跑馬燈，接收端可忽略或僅留存不呈現（與 Tammy 對話：跑馬燈為可選、非試點必要）。

4. 門市與設備

  • target 與門市對應：Request 內 serviceSpecialData_Json.target 為目標叫號機識別值（規格範例 composec030020）。target 與門市／螢幕之命名規則待確認（是否為 merchant_id + account 等組合，由迷客夏提供清單）。
  • 機上盒（STB）：以店編號綁定；設定與驗收時並列店名供人工確認，避免編號誤植。
  • 一店多螢幕：若同一門市有多台叫號螢幕，對應之 target 數量與 POS 外送策略待確認（單一 target 多台同步，或多 target 分屏等）。

5. 測試與上線

項目說明
測試環境 URL待提供 — 供 Tammy 或奧創試送、達鈦整合前驗證（與正式環境分離）。
正式環境 URL待提供 — 驗收通過後交付達鈦設定；達鈦僅更換 endpoint。
試送迷客夏 Tammy 可於測試環境試送；開發階段奧創自測呼叫可接受。
試點門市待確認 — 店編號、target、螢幕數量。

切換步驟（摘要）：

  1. 奧創提供測試 URL → 迷客夏／Tammy 試送 → 完成第 6 節驗收項目。
  2. 確認 target／店編與現場螢幕連線正常。
  3. 奧創提供正式 URL → 迷客夏協調達鈦於試點門市更換 URL。
  4. 營運日監看：準備中／可取餐顯示、離線與錯誤回覆是否符合規格。
  5. 必要時可於非尖峰時段回退至原迷客夏 URL（由迷客夏與達鈦執行）。

6. 驗收項目

新接收端需完成下列九項測試（文字依《叫號機接收端 API 串接規格》第 5 章）。

項目測試方式確認人結果
1. 準備中號碼正常顯示測試環境試送含 From_Store_Preparing（或其他 *_Preparing）；目視螢幕準備中區塊。
2. 可取餐號碼正常顯示試送含 From_Store_OK（或其他 *_OK）；目視可取餐區塊。
3. 多筆號碼同時顯示單次外送多筆 number_content；確認兩區塊同時正確列出。
4. 號碼狀態切換同一號碼由 Preparing 改為 OK（或自名單移除）；確認區塊移動符合整批覆寫規則。
5. 空陣列可清空畫面外送 number_content: []；確認叫號區塊清空。
6. 跑馬燈內容及速度更新試送 newsTicker_content／newsTickerSpeed；確認接收端處理符合約定（試點螢幕不顯示跑馬燈）；必要時以 Response 紀錄為準。
7. 找不到目標設備時正確回傳使用未註冊之 target 試送；確認內層訊息為「找不到目標叫號機」。
8. 目標叫號機離線時正確回傳模擬螢幕未連線；確認內層訊息為「目標叫號機尚未連線」。
9. Response 格式符合既有規格比對欄位名稱、型別與 JSON 字串結構（含 reslut、reesultMd5_ServerSignature 拼字）。

7. 需迷客夏提供之資料

  • 簽章方式與測試用憑證：透過安全管道提供（電子郵件、加密檔或雙方約定之方式），不於本網頁揭露。
  • HTTP 方法（如 POST／GET）及 Content-Type 等連線細節（若規格未載明）。
  • 試點門市清單：店編號、account、target、現場螢幕數量。
  • 外送頻率、逾時與重試：POS 呼叫間隔、連線逾時秒數、失敗是否重送及次數上限（待確認）。
  • 聯絡窗口與可聯絡時段：試點期間迷客夏 IT／達鈦支援時間。
