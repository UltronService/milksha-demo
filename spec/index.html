已確定事項

  • 掃描槍：有線，接機上盒；全台同款 Sunmi 小锃1／小锃2。
  • 杯貼條碼：格式為「取餐號碼,訂單類型」，由接 POS 的貼紙機印出。訂單類型：1 內用、2 外帶、3 外送、4 UberEats、5 Foodpanda、6 你訂。
  • 選項 B（掃碼流程）：POS 送「製作中」；掃一次＝可取餐，再掃一次＝從畫面拿掉。POS 也可能直接送可取餐。
  • 螢幕顯示：只顯示「製作中」「可取餐」兩區；取完餐直接拿掉，不做歷史區（2026-09-29 定案）。
  • 號碼：不自動移除（需依掃碼或 POS 狀態異動）。
  • 硬體：獨立 16:9 橫式螢幕，不穿插廣告。
  • 斷線：保留最後狀態，掃描槍照常可用；重連／重開機向 POS 要完整名單，並把離線期間掃描同步回 POS。
  • 樣式：規則經雙方測試定案後由奧創設定，迷客夏不自行調整。
  • 支援：門市問題先找奧創 Line 客服；奧創提供操作影片與說明網頁。
  • 試點：十月底新開松山店，試點三個月。
  • 費用：不收串接費，月費多 50 元；POS 改版、佈線、硬體由迷客夏負擔。

Socket 技術文件重點

連線與資料格式

  • 機上盒 App 開 TCP Server，等待 POS 連線；訊息為 JSON。
  • 連上後機上盒送出字串 fullTicketStatus，POS 回傳完整叫號狀態；之後僅送異動。
  • 心跳機制另議。
  • POS 開機時名單一定為空，之後向 ODO 撈取線上／外送單。

狀態碼

代碼 意義
1已接單
2製作中
3可取餐
0完成

叫號螢幕端：每 90 秒自動重叫一次、最多兩次（由螢幕自行處理）。

網段規格（技術文件）

  • POS：10.3.X.21～10.3.X.23
  • 叫號機／螢幕：10.3.X.223

流程概要

  1. 機上盒啟動 TCP Server，POS 連線。
  2. 機上盒送出 fullTicketStatus，POS 回傳當下完整叫號清單（JSON）。
  3. 之後 POS 僅推送狀態異動；叫號螢幕依 Status 顯示於「製作中」或「可取餐」。
  4. 店員以掃描槍掃杯貼：依選項 B 將訂單推進可取餐或從畫面移除（掃碼回傳 POS 之 API 尚待文件補齊）。
  5. 斷線期間螢幕保留最後狀態、掃碼仍可用；恢復連線後向 POS 索取完整名單並補傳離線掃描結果。
  6. 螢幕對可取餐號碼執行 90 秒重叫（最多兩次）。
