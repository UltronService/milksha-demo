叫號機接收端 API 串接規格 — 討論文件

版本 v1.0 · 日期 2026-09-29

資料來源：迷客夏提供之《叫號機接收端 API 串接規格》（本頁內容僅整理該文件，不含其他來源）。

1. 文件目的與角色

本文件提供叫號機顯示廠商進行接收端串接。

  • 發送端：已在線上運行，依既有格式推送資料。
  • 接收端（我們）需完成：
    1. 接收叫號資料；
    2. 將資料顯示於指定門市螢幕；
    3. 回傳處理結果。

Request 與 Response 的欄位名稱、資料型別及結構不可任意修改。

2. 流程圖

3. Request

範例（整理為合法 JSON）

{
  "isEncrypt": false,
  "serviceSpecialData_Json": {
    "target": "composec030020",
    "data": {
      "number_content": [
        {
          "source_type": "From_Store_OK",
          "number": "1488"
        },
        {
          "source_type": "From_Store_Preparing",
          "number": "1985"
        }
      ],
      "newsTicker_content": [
        "歡迎光臨 COMPOSE 臺北信陽店",
        ""
      ],
      "newsTickerSpeed": 8.0
    }
  },
  "merchant_id": "compose",
  "account": "c030020",
  "timeStmp": "2026-07-17-13-17-00:2831",
  "serviceSpecialData_Json_Md5Hash": "8f4e7936a314a6b84af58116b272d0fe",
  "signature": "Base64 簽章字串"
}

欄位說明

欄位型別說明
isEncryptBoolean資料是否加密
serviceSpecialData_JsonObject叫號機顯示資料
merchant_idString品牌代碼
accountString門市帳號
timeStmpString資料產生時間
serviceSpecialData_Json_Md5HashString顯示資料 MD5
signatureString發送端數位簽章

顯示資料欄位（serviceSpecialData_Json）

target：目標叫號機識別值（例："composec030020"）。接收端需依 target 將資料傳送至對應門市螢幕。

number_content：門市目前需顯示的完整叫號資料陣列。

欄位型別說明
source_typeString訂單來源及狀態
numberString顯示號碼（必須以字串處理，不可轉為整數）

source_type（10 種）

接收端需支援下列全部類型，並依完整字串判斷。

source_type來源顯示狀態
From_Store_Preparing門市現場準備中
From_Store_OK門市現場可取餐
From_milksha_point_Preparing迷點準備中
From_milksha_point_OK迷點可取餐
From_FoodPanda_Preparingfoodpanda準備中
From_FoodPanda_OKfoodpanda可取餐
From_UberEat_PreparingUber Eats準備中
From_UberEat_OKUber Eats可取餐
From_Udd_PreparingUDD準備中
From_Udd_OKUDD可取餐

跑馬燈欄位

欄位型別說明
newsTicker_contentString Array跑馬燈文字（空字串可忽略不顯示）
newsTickerSpeedNumber跑馬燈速度

4. Response

範例

{
  "merchant_id": "Milksha",
  "account": "Tammy001",
  "isOK": true,
  "information": "{\"isSuccess\":false,\"information\":\"目標叫號機尚未連線\"}",
  "reslut": {
    "CallingNumberMasterResponse": {
      "result": "{\"isSuccess\":false,\"information\":\"目標叫號機尚未連線\"}",
      "statusCode": "200"
    }
  },
  "resultMd5": "bdb40f2be456e1c382c4fe3dc8e5606c",
  "reesultMd5_ServerSignature": "Base64 簽章字串",
  "isEncrypted": false
}
拼字特殊、不可修改的正式欄位名稱： Request 的 timeStmp；Response 的 reslut、reesultMd5_ServerSignature。

欄位說明

欄位型別說明
merchant_idString商戶代碼
accountString帳號
isOKBooleanAPI 是否正常完成處理
informationString實際處理結果，內容為 JSON 字串
reslutObject叫號機處理結果
resultMd5String回傳資料 MD5
reesultMd5_ServerSignatureString接收端伺服器簽章
isEncryptedBoolean回傳資料是否加密

內層 JSON 字串解析

information 與 CallingNumberMasterResponse.result 為 JSON 字串，例：

"{\"isSuccess\":false,\"information\":\"目標叫號機尚未連線\"}"

解析後：

{
  "isSuccess": false,
  "information": "目標叫號機尚未連線"
}
欄位型別說明
isSuccessBoolean是否成功顯示至叫號機
informationString成功或失敗訊息

isOK = true 只代表 API 正常完成處理；實際是否成功顯示，需看內層的 isSuccess。

建議回傳訊息（四種）

成功

{ "isSuccess": true, "information": "資料顯示成功" }

目標未連線

{ "isSuccess": false, "information": "目標叫號機尚未連線" }

找不到設備

{ "isSuccess": false, "information": "找不到目標叫號機" }

資料錯誤

{ "isSuccess": false, "information": "叫號資料格式錯誤" }

5. 驗收項目

新接收端需完成以下測試：

  • 1. 準備中號碼正常顯示。未測
  • 2. 可取餐號碼正常顯示。未測
  • 3. 多筆號碼同時顯示。未測
  • 4. 號碼狀態切換。未測
  • 5. 空陣列可清空畫面。未測
  • 6. 跑馬燈內容及速度更新。未測
  • 7. 找不到目標設備時正確回傳。未測
  • 8. 目標叫號機離線時正確回傳。未測
  • 9. Response 格式符合既有規格。未測
