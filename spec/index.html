最優先討論：串接架構怎麼選

待討論 最優先

背景

現況：達鈦 POS 已經會把訂單／叫號資料送到迷客夏自己的 API。Socket 技術文件是迷客夏「建議」奧創的做法，尚未定案。

方案 A（迷客夏文件建議）：店內直連

機上盒開 TCP Server，達鈦 POS 在店內網路直接連機上盒送叫號資料；掃碼結果直接回 POS。

優點：快；店內網路即可運作（外網斷也能用）。

缺點：達鈦要新寫串接；掃碼回報通道文件未定義；要固定網段。

要改：達鈦（大）、奧創（中）、迷客夏（無）。

方案 B（負責人提出）：走迷客夏現有 API

達鈦照舊打迷客夏 API（不用改）；奧創機上盒從迷客夏取得叫號資料。B1 奧創定時去讀迷客夏；B2 迷客夏資料更新時轉送給奧創。

優點：達鈦可能完全不用改；奧創不用處理店內網段。

缺點：迷客夏要開讀取或轉送口子，還要能接收掃碼回傳並通知 POS；資料繞雲端一圈會稍慢；門市外網斷線時畫面停住、掃碼無法即時回傳。

要改：達鈦（無或很小）、迷客夏（中）、奧創（中）。

方案 C（比照現有做法）：多打一份到奧創雲端

達鈦用打迷客夏 API 的同樣方式，多打一份到奧創的雲端 API；機上盒從奧創雲端拿資料；掃碼結果由奧創回傳達鈦。

優點：達鈦沿用熟悉格式，改動小於 A；不經迷客夏。

缺點：達鈦仍要小改；同樣繞雲端、外網斷會停。

要改：達鈦（小）、奧創（中）、迷客夏（無）。

會議要問迷客夏的問題

  1. 現有 API 能不能讓奧創讀到叫號資料，或在更新時轉送給奧創？
  2. 掃碼結果能不能寫回迷客夏並通知 POS？
  3. 資料更新多快？
  4. 現有 API 有沒有文件可以提供？
  5. 門市外網穩定度與斷線時的預期行為。

已確定事項

  • 掃描槍：有線，接機上盒；全台同款 Sunmi 小閃1／小閃2。
  • 杯貼條碼：格式為「取餐號碼,訂單類型」，由接 POS 的貼紙機印出。訂單類型：1 內用、2 外帶、3 外送、4 UberEats、5 Foodpanda、6 你訂。
  • 選項 B（掃碼流程）：POS 送「製作中」；掃一次＝可取餐，再掃一次＝從畫面拿掉。POS 也可能直接送可取餐。
  • 螢幕顯示：只顯示「製作中」「可取餐」兩區；取完餐直接拿掉，不做歷史區（2026-09-29 定案）。
  • 號碼：不自動移除（需依掃碼或 POS 狀態異動）。
  • 硬體：獨立 16:9 橫式螢幕，不穿插廣告。
  • 斷線：保留最後狀態，掃描槍照常可用；重連／重開機向 POS 要完整名單，並把離線期間掃描同步回 POS。
  • 樣式：規則經雙方測試定案後由奧創設定，迷客夏不自行調整。
  • 支援：門市問題先找奧創 Line 客服；奧創提供操作影片與說明網頁。
  • 試點：十月底新開松山店，試點三個月。
  • 費用：不收串接費，月費多 50 元；POS 改版、佈線、硬體由迷客夏負擔。

Socket 技術文件重點

連線與資料格式

  • 機上盒 App 開 TCP Server，等待 POS 連線；訊息為 JSON。
  • 連上後機上盒送出字串 fullTicketStatus，POS 回傳完整叫號狀態；之後僅送異動。
  • 心跳機制另議。
  • POS 開機時名單一定為空，之後向 ODO 撈取線上／外送單。

狀態碼

代碼 意義
1已接單
2製作中
3可取餐
0完成

叫號螢幕端：每 90 秒自動重叫一次、最多兩次（由螢幕自行處理）。

欄位

欄位 說明
Store_ID門市識別
Order_ID訂單識別
Pickup_Number取餐號；0168～9999 或第三方平台號碼
Order_Type訂單類型（對應杯貼類型碼）
Status狀態碼（見上表）
Create_Time建立時間
Booking_Time預約時間
Update_Time更新時間
Total_Qty總數量
Total_Time總時間（文件定義）
Order_Items品項陣列：Item_Code, Item_Name, Count, Unit_Price

網段規格（技術文件）

  • POS：10.3.X.21～10.3.X.23
  • 叫號機／螢幕：10.3.X.223

流程概要

  1. 機上盒啟動 TCP Server，POS 連線。
  2. 機上盒送出 fullTicketStatus，POS 回傳當下完整叫號清單（JSON）。
  3. 之後 POS 僅推送狀態異動；叫號螢幕依 Status 顯示於「製作中」或「可取餐」。
  4. 店員以掃描槍掃杯貼：依選項 B 將訂單推進可取餐或從畫面移除（掃碼回傳 POS 之 API 尚待文件補齊）。
  5. 斷線期間螢幕保留最後狀態、掃碼仍可用；恢復連線後向 POS 索取完整名單並補傳離線掃描結果。
  6. 螢幕對可取餐號碼執行 90 秒重叫（最多兩次）。
